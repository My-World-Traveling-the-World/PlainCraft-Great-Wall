# 万里长城「专属群系」完整实施方案（选项 A）

- 日期：2026-10-06
- 目标：给长城做专属群系，**只在长城路线上出现**，群系内不长外来树、只长指定树木
- 前置已确认：**不碰红线**（用 Lithostitched 官方 API + 数据包）
- 树的来源：**优先用整合包已有 mod 的树，没有则用原版**

---

## 零、大白话总览

要做的就三件事：

1. **注册一个「长城群系」** —— 写 2 个 JSON（1 个让游戏认识它，1 个描述它长什么样）
2. **沿着长城路线贴标签** —— 抄圣域一个文件（`SanctuaryBiomeWriter`）
3. **群系里放什么树** —— 写 2~3 个 JSON，引用 mod 或原版的树

**总共 8 个新文件 + 1 个修改。其中 6 个是纯 JSON（不写代码）。**

---

## 一、为什么不用破红线（决定性的技术依据）

### 1.1 Lithostitched 提供官方入口

`lithostitched-1.8.0+beta6` **已在你的整合包里**。它的公开 API：

```java
// dev.worldgen.lithostitched.api.worldgen.biomeinjector.BiomeInjector
public abstract List<Holder<Biome>> possibleBiomes();   // ← 官方"加群系"入口
```

**它内部自己调 `possibleBiomes()`，我们只是给它提供数据。** 我们自己的代码一行都不碰那个方法。

### 1.2 数据包路径（真实范例已提取）

```
data/<命名空间>/lithostitched/biome_injector/<任意名>.json
data/<命名空间>/lithostitched/region/<任意名>.json
```

**真实范例 1**（Terralith 的 `biome_injector`）：
```json
{
  "type": "lithostitched:replace_fully",
  "dimension": "minecraft:overworld",
  "targets": "terralith:skylands_autumn",
  "replacement": "minecraft:deep_ocean"
}
```

**真实范例 2**（Lithostitched 自带 `region/overworld.json`）：
```json
{
  "dimension": "minecraft:overworld",
  "biomes": "#minecraft:is_overworld",
  "weight": 100
}
```

### 1.3 五种注入类型（javap 提取）

| type（codec id） | 字段 | 用途 |
|---|---|---|
| `lithostitched:add_points` | `biome`, `points` | 往气候表加点 |
| `lithostitched:dispatch_alternate_layout` | `biome`, `points` | 分发备用布局 |
| **`lithostitched:force_placement`** | `biome`, +气候/区域参数 | **强制在指定条件生成** ← **选项 A 用这个** |
| `lithostitched:replace_fully` | `targets`, `replacement` | 完全替换 |
| `lithostitched:replace_partially` | `targets`, `replacement` | 部分替换 |

**选项 A 的关键**：`force_placement` 的 `ParameterBuilder` 支持 **`region(ResourceKey<Region>)`** —— 可以限定"只在某个 region 内生成"。

```java
// ParameterBuilder API（javap 提取）
public abstract ParameterBuilder climateRange(ClimateParameter, double, double);
public abstract ParameterBuilder region(ResourceKey<Region>);      // ← 区域限定
public abstract ParameterBuilder densityFunctionRange(...);
```

## 三、树木来源（按用户要求：优先 mod，没有则原版）

### 3.1 整合包已有的树资源（已实测）

| mod | placed_feature 数量 | 可用树举例 |
|---|---|---|
| **BiomesOPlenty** | **322** | `biomesoplenty:aspen_tree`、`cypress_tree`、`big_oak_tree`、`dead_tree_wasteland` |
| **GoodEnding** | 58 | `goodending:cypress_tree_checked`、`natural_cherry_checked`、`marsh_swamp_tree` |
| **Galosphere** | 24 | （地下群系为主） |
| **ecologics** | 9 | |
| **原版** | 丰富 | `minecraft:oak`（4~6 格）、`birch`、`spruce` |

### 3.2 选型建议

| 位置 | 用什么 | 理由 |
|---|---|---|
| **长城核心区（走廊内）** | **矮树**：`minecraft:oak`（4~6 格）或 BOP 的小型树 | 你要的「低矮」 |
| **长城边缘带** | **高树**：`minecraft:birch`/`spruce`，或 BOP `aspen_tree`/`cypress_tree` | 你要的「高大树木放最边缘」 |

### 3.3 硬依赖 vs 软依赖（**重要决策点**）

**问题**：如果群系 JSON 里直接引用 `biomesoplenty:aspen_tree`，那么**没装 BOP 的玩家会加载失败**。

**两个方案**：

| 方案 | 做法 | 优劣 |
|---|---|---|
| **A1（推荐）** | 群系里**只放原版树**；mod 树用**可选数据包**（单独一个 datapack 文件，装了 BOP 才生效） | 无硬依赖，安全 |
| **A2** | 直接引用 mod 树，把该 mod 加进 `depends` | 简单，但引入硬依赖 |

**我建议 A1** —— 长城的 `fabric.mod.json` 目前依赖很干净（只有 loader/mc/java/fabric-api），保持这样。

## 四、为什么"注册群系"和"贴标签"两件都要做

这是关键机制（javap 实证）：

```java
// ChunkGenerator.applyBiomeDecoration 字节码，偏移 163-172
biomeSet.retainAll(biomeSource.possibleBiomes());
```

游戏在长树之前做一次「求交集」：

| 场景 | 结果 |
|---|---|
| **只贴标签，不注册**（群系不在表里） | `retainAll` 把群系删掉 → **该区块 `stepFeatures` 为空** → **连草、花、矿石都不生成** |
| **只注册，不贴标签** | 群系按气候自然生成，**不会精确落在长城路线上** |
| **两个都做** | ✅ 群系精确贴在长城处，且特征正常生成 |

## 五、四个必须知道的坑

### 坑 1（最重要）：Lithostitched 环境下，圣域的注入手法是失效的

javap 实证：
```
InjectorBiomeSource extends net.minecraft.class_1966    ← = BiomeSource，不是 MultiNoiseBiomeSource
BiomeInjectorManager.applyBiomeInjectors 偏移 474: setBiomeSource(...)   ← 整体替换
```

**后果**：
- 圣域 `BiomeSourceMixin` 的 `instanceof MultiNoiseBiomeSource` 判断**失败**
- `MultiNoiseBiomeSourceMixin` 的 Mixin 目标类**不匹配**
- **两个 mixin 在你整合包里双双失效**

**对我们的意义**：① 印证「写 chunk 数组」（`SanctuaryBiomeWriter`）才是真正有效的手法；② **我们本来就不抄那两个 mixin**。

### 坑 2：`retainAll` 会删群系（见 §4）

### 坑 3：新群系默认材质是 STONE

`decay/BiomePaletteIndex.java:82-91` 兜底返回 `Variant.STONE`。
**必须把长城群系加进 `palette_*.json`**，否则静默用错材质（看起来没报错，实际是石头）。

### 坑 4：加 worldgen 文件 → 旧存档失效

`GenerationResourceFingerprint` 把 `worldgen/` 算进世界指纹 → 哈希变化 → `WORLD_RECIPE_MISMATCH`。
**用户已确认不考虑旧存档**，但必须**开新世界**。

## 六、与长城现有架构的兼容性（已核实，无冲突）

| 检查项 | 结论 |
|---|---|
| 群系覆写 vs 长城 CAPTURE | **无冲突**。CAPTURE 读的是 `getPersistedStatus().isOrAfter(FEATURES)` 的区块，且只遍历 `chunk.getBlockState`（与群系无关） |
| 群系覆写 vs 三红线 | **不冲突**（不碰 `possibleBiomes` 方法、不同步 getChunk、不 join future） |
| 群系覆写 vs `TreeFeatureMixin` | **叠加而非冲突**。`TreeFeatureMixin` 按走廊快照取消越界树，是兜底 |
| 群系覆写 vs recipe 指纹 | **需要确认**：新增 `worldgen/` 会让 `templatesHash`/`terrainHash` 变化 → 旧存档失效（已知） |
