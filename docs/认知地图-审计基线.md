# 长城项目认知地图（审计基线）

日期：2026-10-03。生成方式：5 个并行子代理深度只读分析 + 主代理第一手通读核心文件。
**本文档是理解与风险识别，不是签收，不含任何代码改动。**

---

## 一、这个 mod 是什么（一句话）

把整堵万里长城当作**世界生成流程的一部分**：锁外异步规划，最后在 owner chunk 上原子写入。
墙折线 = 纯函数 `f(seed, axis, segment index)`，段长 2048，层层派生。

---

## 二、完整数据流

```
规划期（纯函数，可离线重算，锁外）
seed → Axis → AnchorField(横向±384) → Hermite载波 → RidgePlanner(残差±192)
  → 2048点折线 → 水文 → 站点 → 高度日程 → 根点选址(RootSearch) → 构件 → 体素

施工期（锁外异步 + 锁内原子写）
VanillaGateMixin钩chunk状态 → WorldServices → ProductionSession.beforeLight
  → runOwner → cellsForChunk(触发面) → loadCell → realizationOwners(捕获面)
  → capture(FEATURES租约+结构引用) → SurfaceProbe(探针) → RealizationPlanner
  → ComponentAssembly(构件→体素) → ChunkPlanCompiler(owner裁剪+负空间裁决)
  → ChunkWallWriter.apply(锁内原子写+marker+heightmap)
```

## 三、五大红线（项目宪法）

| 编号 | 规则 |
|---|---|
| R1 | worldgen 不同步 `getChunk`/`join`/`get`/`possibleBiomes`；只在锁外挂依赖 |
| R2 | 跨线程共享值仅 不可变对象 + ConcurrentHashMap + 承载的 promise |
| R3 | 不调用或修改 `possibleBiomes()` |
| P4 | PREPARE(FEATURES only)→CAPTURE→durable T0→APPLY(owner)→LIGHT；CAPTURE 不等其他 APPLY |
| P5 | manifest/T0/门/烽火/驻军历史不可当缓存清空；损坏 fail-closed |

## 四、核心契约（逐条已核实）

1. **supports 键 = world 坐标 `(x, walkY, z)`**（`RealizationPlanner:416`），所有消费方一致。
   ⚠️ 陷阱：同一 world-XZ 存在两套 y-key —— `supports`(ProbeResult) 用 **y=walkY**，
   `columns`(ColumnView) 用 **y=0**（`SnapshotColumnView:39`）。混用即 null→T0_MISSING。
   ⚠️ 例外：WALL 构件的 supports 键 y = **逐列插值的 walkY**（`height(stations,s)`），
   非站点常数 walkY，与其余构件是两套约定。

2. **探针窗口 `[walkY-32, walkY+6]`**，三层支撑 `solidSupport(h-1/h-2/h-3)`，drop≤12。
   垂直窗口魔法数（-35/-32/+6/+8）散落多处，无集中常量。

3. **负空间 OWNED_VOID 白名单是固定 switch**（`ChunkPlanCompiler.replaceableVoid`），
   不随标签扩展——材料分类（承重/可替换）与负空间权限（能否挖空）是两件独立的事。

4. **优先级裁决**（`ChunkPlanCompiler.winner`）：FORT 800 > GATE/WATER_GATE 700 >
   ENEMY_TOWER/BEACON 600 > RAMP/END_CAP 550 > WALL 400。

5. **保护的五来源**（`SnapshotColumnView.protectedAt`）：catalog 分类 / thin-ice 非自然 /
   blockEntity / immutableBlocks / protectedStructures。

## 五、五领域核心发现（按严重度）

### 5.1 兼容层 + mixin —— WallArchBackfill 四重断裂（S2 致命）

**`WallArchBackfill` 整条链四个环节各自独立断裂**（已独立验证）：

| 环节 | 断裂 | 位置 |
|---|---|---|
| prepare | `hop.join()` 同步死等（违反 R1） | `WallArchBackfill:68` |
| compileArch | 空体素假 arch（before=air after=air，等于没挖洞） | `:159-186` |
| buildPlans | 用错 `OwnershipGuard` 重载 → GATE_BACKFILL 恒 CONFLICT → prepare 必炸 | `:88` + `OwnershipGuard:29` |
| applyLoaded | 调只认 INITIAL 的 writer → 必抛异常 | `:127` + `ChunkWallWriter:28` |

**结论：S2 道路穿墙功能当前 0 可用。**

配套缺口：freeze solver 未实现（`GateLedger.freeze` 只 flip state 不算 groundY/profile）、
`RoadAdapterState.propose/frozen/adoptFrozen` 全部 throw `profilePending`、
`Passage.physicallyReady` 恒 false —— 道路高度协商 + 门物理打通整链不可用。

### 5.2 规划/几何 —— 规划期 vs 施工期判据不同源（S1C 隐患）

| 风险 | 内容 |
|---|---|
| R1（最严重） | `RootSearch.footprintStep` 采**未旋转** origin±24（`RootSearch:204-205`），`Fort.footprintSupported` 用**旋转** frame（`Fort:188`），非 90° 轴上柱集合不同 → root fort0 可能规划判合格、施工判失败 |
| R2 | 支撑谓词双源：规划用 `foundationEvidence`（3 层 support flag），施工用 `SurfaceProbe`（SUPPORTED+drop≤12+保护） |
| R3 | walkY 双源：规划 entranceFrame.walkY = COARSE centerHeight+20，施工用 REFERENCE 站表 walkY |
| R4 | axis 方向 ≠ 折线实际切线（RidgePlanner 残差致局部旋转） |

### 5.3 生产管线 —— 三个阈值不等价（触发面真实故障路径）

| 风险 | 内容 |
|---|---|
| 最严重 | `cellsForChunk` 先调 `Projection.nearest`，后者对 >1024 块 chunk 会 throw OUT_OF_BOUNDS（`Projection:56`），而 planner 空窗口阈值是 1312 块（`PlannerScheduler:184`）→ **1024~1312 横向带内 chunk 会被直接炸掉生成**，三阈值 196/1024/1312 不对齐 |
| 中 | 站点分支 owner 外扩不对称：min 侧净 -2、max 侧净 +1（`CoveragePlanner:83` addOwners 在 worldBounds 已 -1 后再 -1） |
| 中 | `cellCenter` 死代码承载"中心 chunk=owner"错误语义 |
| 中 | `leaseRadiusChunks=4` 时 9×9 halo 占满 81，withReferenceChunks 引用兜底无余量 |

✅ 好消息：`cellsForChunk` 已字面调用 `realizationOwners.contains(chunk)`（`CoveragePlanner:58`），
触发面/捕获面**结构上已统一**。

### 5.4 持久化 —— "实现完成 ≠ 已接线"（S2/S3/S5 鸿沟）

| 缺口 | 内容 |
|---|---|
| FaultInjector 零调用 | 18 个故障点定义但 src/main 零 `.hit(` 调用 → S5 压测缺地基 |
| 永久历史未接线 | HistoryJournal/RecoveryCoordinator/GateLedger/WallWorldState 在 `ProductionSession` 全未构造 → fail-closed 恢复从未真实执行 |
| fail-open 占位 | `RecoveryCoordinator.inspectGate`/`verifyEvidence` 未校验却返回 CLEAN，与类头"failures stay visible"矛盾 |

✅ 好消息：S2 文档记载的 HistoryJournal 旧骨架偏差（构造签名/open/state/checkpoint/readAllLines/close join）
在当前源码**已全部消除**；预算两 arena（terrainBytes/compiledBytes）当前接线正确。

### 5.5 构件层 —— 尺寸/边界不一致 + off-by-one

| 风险 | 内容 |
|---|---|
| Fort off-by-one | `Fort.localBounds` minY=-32，但 `foundation(lower-1)` 在 drop=12 时最深到 -33 → 最深 1 格地基空循环放不进去（`Fort:38` vs `:81`） |
| FORT 尺寸三处不一致 | Fort=-32 / FortPlaceholder=-33 / SiteScheduler=-33 |
| Ramp 双 bounds | 接口对称包络 `localBounds()` vs 私有非对称 `LOCAL`，`compileBetween` 用 LOCAL 冻结，height>32/frame/mirror 改动即越界抛异常 |
| 入口矩形无真源 | GroundEntranceContract 的"哪面是入口"常量散布 Gate/EnemyTower/Fort/Ramp 四文件 |

## 六、元结论（贯穿所有发现）

**架构方向是对的**（锁外异步、纯函数分层、fail-closed、原子写都做得好），
但**有两个系统性纪律没守住**：

### 纪律 1：规划期 vs 施工期判据必须同源
同一套几何/证据/坐标/谓词的判定散落两处，靠"约定一致"而非"强制一致"。
每次真实地形撞上才补一个共享判据（GroundEntranceContract、realizationOwners.contains 都是这么来的），
但还有更多散落的没被发现（未旋转/旋转足印、支撑谓词双源、walkY 双源、三阈值不等价）。

### 纪律 2：实现完成 ≠ 已接线
S2/S3/S5 大量类写好了、单测过了，但**没接入生产 bootstrap**。
审计看"文件存在 + 单测通过"会误判为"已完成"，实际是"隔离的漂亮零件，没装进机器"。
这是最大的陷阱，会让审计高估进度。

## 七、三个最该被审计盯住的点（跨领域共识）

1. **WallArchBackfill 四重断裂**（S2 致命，四环节独立断，真实运行必炸）
2. **规划/施工判据不同源**（未旋转/旋转足印、支撑谓词双源、walkY 双源、三阈值不等价）
3. **永久历史层未接线 + fail-open 占位**（HistoryJournal/RecoveryCoordinator/GateLedger/WallWorldState
   未进 ProductionSession，inspectGate/verifyEvidence 不校验却返回 CLEAN）

## 八、我（主代理）独立发现的架构隐患

**`model.WallTypes`（号称"纯模型、零 MC 依赖"）反向依赖了 `component.GroundEntranceContract` → `generation.SurfaceProbe`**。
依赖倒置：`ComponentInput.entranceEvidence` 字段让纯模型层反向依赖高层。
这本身不一定是 bug，但打破了"纯模型零 MC 依赖"的设计边界，是补丁式修复侵蚀架构的证据。
