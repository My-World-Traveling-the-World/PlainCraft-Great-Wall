## 2. 取消、异常、重试与关闭

每次 executor turn 新建 task scope，不复制 ThreadLocal。
generation 对外取消与内部 settlement 分离；runtime/idle 槽位跟随 settlement，
STOPPING/暂停不会直接清零伪造排空。重试保持原候选顺序，
玩家预设道路不被失败后的 A* 重试偷偷替换。

收尾只读审查发现并修订三处本批局部风险：

- 保存原始持久化 RoadData 的成果归属，异常/阶段间取消仍能回收；
  用实际 `complete()` 是否接受判定，不能用先前 `isCancelled()` 快照代替。
  primary/supplemental 接受后保留，未接受的 reuse/candidate 回收。
- 同边 GENERATING 请求去重；不可变 attempt + CHM 身份校验防旧完成盖新任务。
  epoch/stopping/提交拒绝/发布异常按自己的 token 移除，不删除新 attempt。
- 批准的 public 异步入口获取共享 slot，真实 settlement 后释放；
  idle 用同包预留入口，runtime 内部原预留不双计。

上述有本轮新 helper 行为反例，不代表真实道路与所有生命周期出口已验收。

尚未证明的生命周期部分：

- `Road.generateRoadAsync` 返回裸 future，缺独立内部 cleanup 信号；generation
  settlement 不能证明所有 CPU/snapshot/pin 完全释放。
- `ThreadPoolManager.PrioritizedRunnable.run` 停止/门控可能不执行 delegate，
  future 可能永久 pending；取消后完整 drain **未证明**。
- 进度/计时线程局部数据的异步聚合与同 JVM A→B→A/停止重启 **NOT_RUN**。
- 已成功的手动 generation 在服务器发布被 epoch gate 跳过时，
  token 会移除，但持久化成果回收仍未闭合。
  关服 write gate 拒绝清理会显式异常，**持久化清理重试未实现**，
  不把这些债务写成“已成功清理/正常排空”。
