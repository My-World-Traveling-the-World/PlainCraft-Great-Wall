## 结论与边界

新世界的实物楼体和墙身确已接入生产，不能因此推导所有地形、整个墙身循环和道路穿门均已完成验收。本轮确认 **两个 P1 风险、三个有计数证据的 P2 优化点**。最先修整墙相位，再补高地失败处理；性能优先考虑精确投影索引与重复完整编译。

## W1：接口 24 格之后“三垛一缺”跳相（P1）

`src/main/java/local/plaincraft/greatwall/component/ImportedRibbonSection.java:68` 用全局里程取模四；`:75` 仅在接口前 24 格改用端面距离。二者没有保证边界相位相等。

生产实现器的门楼夹具，接口向外 17～28 格：

```text
port=0 expected=MMM_MMM_MMM_ actual=MMM_MMM__MMM
port=1 expected=MMM_MMM_MMM_ actual=MMM_MMM___MM
```

第二条受回弯几何影响，不单凭它判错误。为隔离转弯因素，另构造完全笔直的站表，调用正式 `ImportedRibbonSection.compileIntervals`，先确认 12 格马道全部存在：

```text
AUDIT_STRAIGHT_PHASE steps=17..28 expected=MMM_MMM_MMM_ actual=MMM_MMM__MMM floors=FFFFFFFFFFFF
```

这证明第 24 格之后有连续双缺，不能用缺站或斜线解释。前轮的第一至第四格真实落块验收仍有效，但不能覆盖整个循环。

**现有守卫盲区**：把全局 phase 改为恒 3（全部缺），保留前 24 格接口覆盖，完整 886 项仍全绿。和前轮“完全破坏接口相位会红”的负控并不矛盾；它们破坏的是不同区域。

**修法**

1. 补五件×四向、直/斜墙、两端接口、第 1～100 格与跨 chunk 产物守卫，先让当前 24→25 反例红。
2. 把相位原点、方向放进连续墙段契约；不要到第 25 格换成不相关的全局原点。
3. 两端都必须缺结尾，长度不匹配时显式安排过渡。不能简单把端口覆盖距离从 24 改成更大常数。
4. 守住马道、腰线、整格/非整格段缝和正反加载，再做普通地形视觉验收。

类型：行为变更。风险是既有冻结 v2 续建边界；不得偷偷改旧配方重放。需要普通世界确认；本轮尚未修复。

## W2：高地硬平台超界，直接使高度求解失败（P1）

`src/main/java/local/plaincraft/greatwall/planning/HeightContractPlanner.java:57` 按建筑占地最高地表 +15 冻结硬平台；`:85` 将 v2 马道上限设为维度顶减 43；`:95` 硬目标超界直接抛 `OUT_OF_BOUNDS`，没有在此形成站点级抑制/断头结果。

合法维度 `[-64,320)`，地表 280，素材/配方摘要同步的高度规划夹具：

```text
AUDIT_HIGH_TERRAIN maxY=320 terrain=280 failure=OUT_OF_BOUNDS message=hard W outside dimension
```

边界保护本身合理，不能删除；问题在于新大模板更容易遇到这个约束，而局部建筑不可容纳没有稳定的站点级决议。**只验证了正式高度规划器的失败；整个启动链最终重试、降级或终止表现尚未实机复现，不能声称已证明卡死。**

方案（行为变更）：先用实际素材最高偏移检查站点可容纳性，产出带原因的站点抑制/断头，再求其余高度。相邻窗口必须共享同一冻结结论。补高地、维度顶边界与跨段一致性集成测试；保持最高点 +15、完整屋顶和门洞空气。需高地真机验收。

## W3：相邻 cell 为同一建筑重复物化完整体素（P2）

`src/main/java/local/plaincraft/greatwall/terrain/RealizationPlanner.java:307` 允许各 cell 对建筑全占地投票，`:308` 直接完整 compile；`:337` 起只在建筑中心 cell 发布。`ImportedTowerBody` 的 compile 遍历完整实物模板。

使用真实澄海楼模板，在 `ExactFootprintTemplate` 边界计数，依次解析三个 cell：

```text
AUDIT_BUILDING_DUPLICATION compileCalls=2 bodyOutputs=1 compiledVoxels=234854
```

这里是夹具完整体素项计数，不是前轮普通服 181,220 体素那份楼的测时，也未包含 inspect/apply 其他调用。计数包装器不代替真实保护故障验收。

方案（纯重构 + 性能）：

1. 从完整体素编译拆出不可变“可建证书”，保留地基、保护、失败原因及所有依赖身份。
2. 周边 cell 对证书投票，发布 cell 物化一次；若先缓存完整组件，应限制在不可变窗口内并按字节/体素额度约束，不能永久缓存每栋楼。
3. 对拍所有体素、实体、战利品、哈希和拒绝原因；验证取消/换代后旧证书不发布。

验收目标是同样输出只完整编译一次；需实际长墙测 CPU 与堆。证书缺失依赖会产生正确性风险，分层提交、每层可独立撤回。

## W4：精确投影反复扫描所有线段，可用保持语义的空间索引（P2）

`src/main/java/local/plaincraft/greatwall/component/ImportedRibbonProjection.java:49` 每列遍历所有有效边；已有逐边盒下界仍需访问每条边。`terrain/RealizationPlanner.java:264` 为实物模式建立投影，随后逐支撑列使用；墙体实现器也会建立投影。

同一门楼生产夹具，259 边、63,057 列：

```text
AUDIT_PROJECTION columns=63057 edges=259 edgeLoopVisits=16331763
AUDIT_PROJECTION_INDEX compared=63057 exactEqual=true leafEdgeVisits=390061
```

审计原型使用包围盒层级索引：最长轴中位分割、每叶最多四边、按下界先查近子树；距离相等按原边序裁决，保留原 Q8 定点运算和首尾延长语义。逐列比较 `globalSQ8/lateral/walkY` 全等。

原型只放在 `scripts/audit/20261119/ProjectionIndexPrototype.java`，生产实现未替换。390,061 是叶边检查数，**没有把树节点访问算进去，也没有据此宣称帧率或耗时倍数**。

下一步（性能 / 行为等价）：

1. 扩到五素材×四向、折返、零长边、同距、端面之外、负坐标与段缝；随机对拍固定 seed 可重现。
2. 不可变窗口只构造一次索引，多 cell 复用，控制建树分配和驻留。
3. 同时量稀疏/密集折返，最坏情况仍可能退化，不能保证所有查询 O(log n)。
4. 真实预热/补建采 p95/p99 与窗口内存后再评价收益；保留逐字段对拍参照。

## W5：保护列发布按体素重复加锁，日志还把体素报成列（P2）

`src/main/java/local/plaincraft/greatwall/generation/WallPlanSupport.java:24` 起每个体素调用一次 `WallRoadGuard.markColumn`。真实门楼组件：

```text
AUDIT_GUARD_MARKING voxelCalls=38571 distinctColumns=2549
```

`WallRoadGuard` 每次需要查表/同步更新；`generation/WallBodyBackfill.java:681` 的 columns 又累计 `voxels().size()`，诊断口径随建筑高度增加，不能代表独立占地列数。

方案（性能 / 行为等价）：先按 chunk 收集 256 列位图，再批量合并，时间戳每块一次；日志分别报体素、独立列和 chunk。所有 owned air 列、边缘 padding 和保护保留期限必须不变。逐列对拍保护 API 并做竞争/清理测试，再测真实锁开销；不能直接省掉“空气体素”保护。

## 跨模组：路仍止于墙脚，门洞不等于公开通道

探针先定位正式门楼组件的真实 `OWNED_VOID`，再按正式发布口径注册保护：

```text
AUDIT_ROAD_DOOR actualVoid=true blocked=true pos=Point3i[x=358,y=65,z=156]
```

`WallRoadApi.blocks` 接受 Y，但当前保护实际是 XZ 列。门洞上方墙/屋顶与空气同列；道路适配日志也写明止于墙脚。双方生产源码未找到 `NegotiatedGateService.request` 的消费调用。

这不是已知旧能力被模板重制丢掉，而是后续完整穿门功能尚未接通。未来应增加带通行高度、方向和有效期的通道证书，只放行合法门道；不能整列取消保护。需要道路/长城/河流真实组合验收。

## 架构与未发现问题的方向

- 本轮扫描 main/client 共 262 个生产 Java，按去注释/空行统计，无文件超过 1000 有效行。`ProductionSession` 约 927、`GreatWallCommands` 约 902；优先按证书、所有权、窗口生命周期拆职责，而非只分文件。
- 暂无证据要求换整套几何、DP 或新建总调度器；投影索引和组件物化先做，收益有可测目标，风险边界也更小。
- 既有前缀缓存和分窗产物反例仍有效，不能用无验证的重置认领/缩窗口改变已冻结产物。
- 本轮未动最高点地基、模板容器战利品、驻军/点火、河流顺序、长桥正弦或存档 schema。
- 未运行新的普通世界、整合包、4096 预热、FPS/MSPT、全长周期建筑视觉或开箱数量统计；没有操作玩家建筑源存档或安装 JAR。
