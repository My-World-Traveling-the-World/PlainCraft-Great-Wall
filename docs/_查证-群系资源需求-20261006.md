### B8. 🔴 圣域怎么把群系挂到主世界 —— **运行时注入，不改注册表**

机制为**双 Mixin + 一个注册表外运行时表**：

**（1）`mixin/BiomeSourceMixin.java`** — `@Mixin(BiomeSource.class)`，`:42` `@Inject(method = "possibleBiomes", at = @At("RETURN"), cancellable = true)`：

## C. 低矮树木 feature 的构造

### C10. 一个"矮树" feature 需要哪些字段

以 `sanctuary_vanilla_grove.json` + `sanctuary_vanilla_trees.json` 为参照，"放矮树"实际是**两层**：

**第一层 — `configured_feature`（定义"长什么树"）**
用 `minecraft:random_selector` 做树种随机：
- `type`：`minecraft:random_selector`
- `config.default`：默认项的 **placed_feature ID 字符串**
- `config.features[]`：`{ "chance": <float>, "feature": <placed_feature ID> }` 列表

（`RandomFeatureConfiguration` 的字段名经 javap 验证：`features` = `List<WeightedPlacedFeature>`、`defaultFeature` = `Holder<PlacedFeature>`；与 JSON 中的 `features`/`default` 对应。）

**第二层 — `placed_feature`（定义"在哪、多密地放"）**
- `feature`：指向 configured_feature 的 ID
- `placement[]`：有序 modifier 链。圣域用的 5 段是：
  1. `minecraft:count`（数量，`count: 3`）
  2. `minecraft:in_square`（区块内随机散布）
  3. `minecraft:surface_water_depth_filter`（`max_water_depth: 0` 排除水中）
  4. `minecraft:heightmap`（`OCEAN_FLOOR`）

**⚠️ 与长城自有护栏的耦合（必须知道）**：

1. `mixin/TreeFeatureMixin.java:15-33` 对 `TreeFeature.place` 做 HEAD 注入，在 `services.productionFixture()` 为真时，任何**与城墙走廊相交的树都会被取消**（`:29-31` 走 `services.vegetation().intersects(...)` → `callback.setReturnValue(false)`）。该 mixin 作用于 **`TreeFeature.class` 本身，不区分命名空间** —— 所以**长城自己的矮树只要用 `minecraft:tree` 类型，同样会被自己的护栏抑制**。这是设计使然（城墙走廊内不留树），但"长城自己的树"若期望长在墙边，就会与护栏冲突。

2. `generation/TreeBoundsCatalog.java` 的树冠半径目录**只认原版类型**，且对未知类型直接抛 `unsupported`：
   - `:153-162` trunk placer 白名单：`straight`/`giant`/`forking`/`fancy`/`dark_oak`/`mega_jungle`/`bending`/`upwards_branching`/`cherry`
   - `:29-30` + `:164` foliage placer 白名单：`blob`/`spruce`/`pine`/`acacia`/`bush`/`fancy`/`jungle`/`mega_pine`/`dark_oak`/`random_spread`/`cherry`
   - `:243-248` decorator 白名单：`trunk_vine`/`leave_vine`/`cocoa`/`beehive`/`attached_to_leaves` → 1；`alter_ground` → 5
   - `:236-240` `type()` 强制要求 `minecraft:` 前缀

   **好消息**：矮橡树用的 `straight_trunk_placer` + `blob_foliage_placer` 都在白名单内（`straight` → trunkRadius 0；`blob` → `radius+4` = 6）。**坏消息**：若给树加 `minecraft:beehive` 之外的第三方 decorator（例如 `alter_ground` 之外的），`TreeBoundsCatalog:247` 会抛 `unsupported("unknown tree decorator")` → `WallFailure`。

3. `TreeBoundsCatalog:60-78` 记录了**用户明确授权的保留项**：编码失败的第三方树 WARN 后跳过、不阻断 freeze。这是既有决策，不因本次新增树而改变。

### C13. 🔴 长城能不能直接复用原版 placed_feature？—— **能，且这是首选路径**

**结论：可以完全复用，不必自建树定义。**

证据链：

**(1) 原版 placed_feature 的粒度正好够用。** jar 内 `data/minecraft/worldgen/placed_feature/oak_checked.json` 完整内容：

```json
{
  "feature": "minecraft:oak",
  "placement": [
    {
      "type": "minecraft:block_predicate_filter",
      "predicate": {
        "type": "minecraft:would_survive",
        "state": { "Name": "minecraft:oak_sapling", "Properties": { "stage": "0" } }
      }
    }
  ]
}
```

即 `oak_checked` 只是"树苗能活就长一棵橡树"，**没有 count/in_square/heightmap** —— 它是"一棵"的粒度，正适合被上层组合复用。同目录另有 `birch_checked.json`、`fancy_oak_checked.json`，结构与 `oak_checked` 同构。

**(2) 圣域已实证这种引用方式可写。** `sanctuary_vanilla_trees.json:4-7` 直接以字符串引用 `minecraft:oak_checked` / `minecraft:birch_checked` / `minecraft:fancy_oak_checked`，未自建任何树 configured_feature。

**(3) 原版自己也是这么组合的。** jar 内 `data/minecraft/worldgen/configured_feature/trees_plains.json`：

```json
{
  "type": "minecraft:random_selector",
  "config": {
    "default": { "feature": "minecraft:oak_bees_005", "placement": [] },
    "features": [
      { "chance": 0.33333334,
        "feature": { "feature": "minecraft:fancy_oak_bees_005", "placement": [] } }
    ]
  }
}
```

注意原版这里是**内联完整 placed_feature 对象**（`{"feature":..., "placement":[]}`），而圣域用的是**纯字符串 ID**。两种写法 codec 都接受（`PlacedFeature.LIST_CODEC` / `CODEC` 并存，javap 已见 `DIRECT_CODEC`、`CODEC`、`LIST_CODEC`、`LIST_OF_LISTS_CODEC` 四个 codec），**字符串写法更简洁，推荐采用**。

**(4) `trees_plains` 现成但含蜜蜂，需注意。** `placed_feature/trees_plains.json` 的 placement 链为 `count(weighted_list: 0×19/1×1)` → `in_square` → `surface_water_depth_filter(0)` → `heightmap(OCEAN_FLOOR)` → `block_predicate_filter(would_survive oak_sapling)` → `biome`。它引用的 configured 是 `oak_bees_005`（默认）与 `fancy_oak_bees_005`（1/3 概率）。

所以：
- **要"带蜜蜂的原版平原树"** → 直接写 `minecraft:trees_plains`，**零新增文件**。
- **要"干净的矮橡树（无蜂巢）"** → `minecraft:oak` 的高度参数已是 4~6，但 `oak_checked` 缺密度参数，需**自建 1 个 placed_feature** 包装它（照抄 `trees_plains` 的 placement 链去掉 `block_predicate_filter`，或保留它）。**这只需 1 个纯 JSON 文件。**

**（结论）是否必须自己新建？** —— **必须新建的只有 placed_feature 这一层（1 个文件）**；configured_feature 层在"只要橡树"时可以完全省略。若还要树种多样性（橡+桦），再加 1 个 `random_selector` configured_feature。**树形定义（`minecraft:tree` 的 TreeConfiguration）一个都不需要写。**

## 一句话结论

长城的 `worldgen/` 是**完全空白**（六类注册资源全为 0），且**没有任何自有方块/物品/Feature 注册**；因此"长城群系 + 矮树"的最小改动是 **3 个纯数据 JSON**（1 placed_feature + 1 biome + 视需要 1 configured_feature），**树形一个字节都不用自己写**（原版 `minecraft:oak` 的高度参数 4/2/0 正好是 4~6 格）。真正的难点不在"资源文件"，而在**第 6 项：群系如何挂进主世界** —— 圣域用的是注入 `possibleBiomes()` 的 Mixin，而这条恰好撞上长城自己的冻结红线 R3，且长城规格书已明文拒绝复制该实现。**建议先就挂载路径取得授权，再落数据文件。**
