文件：`D:\云游四海-Mod源码\plaincraft-great-wall\src\main\java\local\plaincraft\greatwall\compat\road\NegotiatedGateService.java`。道路软依赖/纯候选JUnit+集成GameTest；R1/R2/P1/P2/P4/P5。

```java

```

record constructors深复制、session非空、完整batch不可空；status白名单`REUSED,FROZEN_PENDING,READY,PROTECTED_GAP,CANCELLED`。

```text
request：只允许S2真实RoadWeaver在路径终检PROTECTED_GAP后调用；请求stage在worldgen锁外。
  先requireWindow包含道路与走廊交点；一次请求域<=2048×2048，长道路分域，不取无限墙AABB。
  Projection计算首次交墙S；term后/无交点返回PROTECTED_GAP附原因，不凭两端横跨判穿墙。
  已有合法门在交点±192S优先复用；排序|deltaS|,GateId；复用还需完整4宽road envelope测试。
  无可复用门，cell=floorDiv(crossingSQ8,128*256)，GateId(wallId,"negotiated",cell)。
  candidateSQ8与同cell既有ledger共同决定合同；既有冻结直接复用，后来的道路适配其高度。
  对候选按固定顺序检验：非planned/realized break、非水门/fort/tower保护足印、距其它有效门至少64S；
    高度窗口和马道足印按同Gate模板；不更改主线路、W或原生gate/tower日程。
  所有affected chunk都已有T0：异步读原证据+回填proof，预检加载部分/已知tombstone，freeze后backfill。
  某chunk未生成：只按自然合同冻结候选，state=PENDING_CHUNKS；不强生成也不读不存在T0；
    production Realization叠加该gate，实际T0不合格→CONFLICT，路保持PROTECTED_GAP，不能换高度偷偷铺。
  ledger.propose(closed batch)→freeze durable→注册端点→返回FROZEN_PENDING；所有chunk实测目标完成才READY。
  任何拒绝输出精确reason；不连续无限挖更宽的洞、不吞失败返回空障碍。
candidateSQ8：cell中心=(cell*128+64)*256，依序offset[0,-16,+16,-32,+32,-48,+48]*256；
  限在[0,terminal)，按完整candidate列表与不可变输入做判定，不取最先chunk就绪者。
onChunkPrepared：已完成T0/Realization后，把当前owner中协商门writePlan加入INITIAL写入；
  journal ACK必须在owner实际apply成功且proof核对之后，不在仅prepared时ACK；此方法只登记待ack关联。
close：释放所有plan lease，取消调用者future，保留已冻结永久门；未提交proposal不可继续晚到publish。
```

道路先到兜底的含义是**永久叠加门事务先于该墙chunk的初建**，不是先无墙放行再回填全墙。天然门600..1000、fort3000..5000日程不因协商门增加而重编号；额外协商门在报告单列，不声称所有最终门间距仍至少600。

## local.plaincraft.greatwall.persistence.AtomicFiles

文件：`D:\云游四海-Mod源码\plaincraft-great-wall\src\main\java\local\plaincraft\greatwall\persistence\AtomicFiles.java`。纯IO/JUnit，P5；S1B/S2可前置复用。

```java
package local.plaincraft.greatwall.persistence;
public final class AtomicFiles {
    private AtomicFiles();
    public static Path resolveUnder(Path root, String relative) throws IOException;
    public static void writeImmutable(Path root, String relative, byte[] content) throws IOException;
    public static void replacePointer(Path root, String relative, byte[] content) throws IOException;
    public static byte[] readChecked(Path root, String relative, int byteLimit,
        String expectedSha256) throws IOException;

```

```text
resolveUnder：root.toRealPath，normalize相对路径，拒absolute/..和任何跳出root的symlink；最终父路径逐级检查。
writeImmutable：同目录随机临时名只用于IO，不混内容hash；CREATE_NEW，write loop、force(true)、close。
  目标已存在读hash相同则删除本tmp并成功，不同报IO_FAILED；否则ATOMIC_MOVE，拒不支持的volume。
replacePointer：同写法，ATOMIC_MOVE+REPLACE_EXISTING；保留上一代由调用者处理；不混淆普通move与原子。
readChecked：size<=byteLimit后有界read，SHA相同返回副本；任何解析失败保留原文件不给空bytes。
```

Windows Java目录fsync可用性需报告：文件force+原子rename保证进程崩溃一致性；不承诺廉价磁盘缓存掉电也100%不丢。双代HEAD/checkpoint及校验用于恢复，无法唯一确定提交链则NEEDS_OPERATOR。不得把平台无法做到的保证写成代码注释里的“绝对安全”。

## local.plaincraft.greatwall.diagnostics.BudgetCache

文件：`D:\云游四海-Mod源码\plaincraft-great-wall\src\main\java\local\plaincraft\greatwall\diagnostics\BudgetCache.java`。纯并发/JUnit，R2/P2；S1 scheduler前置基础。

```java
package local.plaincraft.greatwall.diagnostics;
public final class BudgetCache<K,V> implements AutoCloseable {
    public record Stats(long bytes, long reservedBytes, long pinnedBytes, int entries,
        int waiting, long evictions, long rejected) {}
    private final ConcurrentHashMap<K,V> completed;
    private final Executor owner;
    public BudgetCache(long byteLimit, int entryLimit, int waiterLimit, Executor owner,
        java.util.function.ToLongFunction<V> retainedBytes);
    public CompletionStage<PlanLease<V>> acquire(K key, long reservationUpperBound,
        java.util.function.Supplier<CompletionStage<V>> loader);
    public Optional<V> peek(K key);
    public void invalidate(K key);
    public Stats stats();
    public void close();
}
```

```text
ctor：正限，owner局部LRU/size/pinCount/waitQ/loaderInFlight；公开Stats在CHM单key。
acquire：同key single-flight；byte上界先reserve再start loader，不能算完巨对象再检查内存。
  completed命中加pin，返回新PlanLease(独立view, release在owner执行)。
  无容量逐出未pin最旧项；仍不足进有界队列而不启动loader；单对象upper>limit直接CAPACITY。
  超waiterLimit立即可重试CAPACITY；调用链把它保留pending不能变成无墙；公平排序Priority在上游scheduler。
  loader完成在owner校验actual<=reservedUpper（超出显式估算错误），更新预算，返回lease；异常释放reservation。
  lease.close→pin--，只有0可逐出，唤醒队首可容纳请求；取消caller不取消其他人loader。
peek：无pin只给诊断不可拿它跨async长期使用；invalidate：pin>0标延后删除，0删；不改永久历史。
stats返回已发布快照；所有map节点/字符串/数组/列表以固定保守retained公式计入（对象32、ref8、数组24+元素、String40+2n）。
close：拒新请求、全部waiter exceptional、release owner资源；完成future从inflight identity-remove，旧session不publish。
```

内存限额不是把整个Minecraft堆限制在160MiB，而是本模组缓存。默认段64MiB/256、T0 64MiB、compiled32MiB/1024、history热点8MiB、oracle lane各8MiB临时列，总inflight geometry4、oracle2、caller lease4096、IO事件128。encoded bytes不是retained bytes：以保守公式申请，JFR/heap dump复核后只能提高估算不能隐藏对象。
