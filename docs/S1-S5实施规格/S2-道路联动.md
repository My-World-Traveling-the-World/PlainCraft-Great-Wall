```text
ctor：只保存依赖；在服务公开前，RecoveryCoordinator先在IO恢复journal+活跃shards，再serverOwner装载快照。
  永久门历史分页，find缺热点不能推断门不存在；propose先journal.lookup恢复相关gate，IO完成后再mutate。
  所有mutations回serverOwner，map值整体替换不可变record；同GateId通过owner-local尾future链串行append与publish，
  第二提案必须等第一receipt后再检查revision，不能两个异步append都从同旧revision派生。
propose：expectedRevision必须匹配；无记录new PROPOSED；routes按id排序、同id profileHash不同拒绝。
  合并同封闭batch；缺任一batch成员不允许freeze；后来未知道路不能挤入已冻结批次改高度。
  若已经FROZEN/APPLIED：返回原contract，调用者调整道路坡，不修改门；不一致新提案另记诊断。
  每次revision+1只在GATE_PROPOSED日志durable后publish。
freeze：PROPOSED且batch完备；每route端点侧最多16个1格站。
  对route r,j：可到端点高度区间[terrainY_j-j,terrainY_j+j]，取所有区间交集，再交[W-32,W-7]及基础许可。
  没交集→CONFLICT/PROTECTED_GAP；有交集选clamp(min所有terrainY,low,high)，平局低值。
  sharedProfile[0]=groundY，后站逐步clamp(逐route最低terrainY,prev-1,prev+1)。
  planned门若已按自然g初建：不能直接freeze到另一Y，必须完整backfill proof可行后开新revision；否则保持原高CONFLICT。
  先存不可变contract/proof blob，再GATE_FROZEN force，最后publish FROZEN→PENDING_CHUNKS。
ack：只认同revision/输入hash；cursor单调且<=写集长；conflicts非空→CONFLICT保留坐标；
  无冲突该chunk ACKED，全部affected ACKED才APPLIED；每次ack durable后publish。
find：已准备相关分片的快照Optional，未准备必须先异步lookup；SPI.prepare在返回snapshot前完成该域历史加载。
activeSnapshot只活跃≤4096条，不把4096当永久门上限；满时排队背压，已APPLIED冷历史可回收内存。
```

冻结顺序确定性范围：同一完整提案集合无论到达顺序相同；不同历史批次首次已冻结的门是永久历史，不声称未知未来道路能反向影响过去。原生计划门默认自然合同先存在，后路适配这个高度。

