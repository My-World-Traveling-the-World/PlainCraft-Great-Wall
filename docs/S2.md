## 实质接线缺口：需要明确 runtime session 的来源

冻结 SPI 的 Request 要求 `UUID session`；`registerHeight(UUID,api)` 只登记 UUID→height。
RoadPlanningService 现有调用者只有 ServerLevel 与路线请求；冻结 registry 没有
level→runtime session 的绑定/查询方法。长城 adapter 旧骨架自己 randomUUID，
与 `WorldServices.find(UUID)` 要求的 `production.runtime()` 也不一致。

不能用“只有一个会话就猜它”、seed 派生 UUID、反射读取私有 map 或固定 UUID 来跨世界接线。
建议显式增加 level→session 注册/查询，由长城 server owner 使用反射跨 ServerLevel ABI
注册其已有 runtime UUID，Road 只拿 immutable UUID。closeLevel/closeSession 清关联。
**尚未自行发明并落地该冻结 API；需要用户确认这一接法。**

拟议最小增量是 registry 的 `bindSession(ServerLevel, UUID)` 与
`session(ServerLevel): Optional<UUID>`，不是新的随机 UUID。
绑定必须在对应 server owner 上、使用 `WorldServices` 已有 runtime 身份；
同 level 不同 UUID 重绑定拒绝，closeLevel 清对应绑定，
closeSession 清该 UUID 的全部绑定。跨映射的 ServerLevel 实参仅反射传递，
Request 内仍只传不可变 UUID 与 DTO。未绑定且已有墙 provider 时必须显式 pending/失败，
不得伪装“无墙”。WorldServices 的 `session()` getter 已有 S3 第 730 行规格，
但**level→session 的 fork registry 增量并不在冻结签名中**，故单列审批。
