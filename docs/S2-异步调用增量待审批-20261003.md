## 为何这是实质接口分叉

【已验证，源码】`S2-道路联动.md:369-383` 要求所有自动/手动/coarse/full/local-repair
经 `RoadTerrainPlanningPipeline.planAsync`，同时要求未列出的既有 public
签名/行为保持。最新批准书还要求冻结清单以外的增量单列审批。

现有直接同步调用仍在 `RoadPlanningService:664/900/1701`、
`RoadPathCalculator:862`。生成消费链是：

```text
RoadGenerationService.generateTaskResult(...) -> GenerationResult
  -> generateTaskWithFallback / generateTaskInternal
  -> Road.generateRoad(...) -> RoadData
  -> RoadPathCalculator.calculateAStarRoadPathDetailed(...) -> PathCalculationResult
  -> RoadTerrainPlanningPipeline.plan(...) -> Result
```

锁外墙准备是 future，不能用 join/get 把它塞回以上同步返回值。
另一个独立缺口：Registry 已有 session(level)，但没有公开的 provider-presence
判据；不能拿 Optional.empty 来断言“没有墙”，因为“有 provider 但尚未绑定”
按已批准合同必须显式 pending/失败。

## 迁移约束

- 原同步 public 签名保留。没有 provider 时原行为保持；有 provider 的请求必须走
  真正完成传播的异步入口，旧同步分支若无法取得合法准备结果须显式拒绝，不忽略墙。
  这是需要用户确认的兼容边界，不自行把旧返回值改成 future。
- 实际自动/手动调用者迁移；coarse/full/local-repair 用已冻结 planAsync，
  不只新增无人调用的重载。内部 private continuation 可随此迁移，算法/重试范围不变。
- 没有 session 且已有 provider：显式 pending/失败，不生成随机 UUID，不返回无墙成功。
- 不以副作用 `whenReady` 阻塞初始 provider 规划；端点副作用仍按 readiness 合同执行。
- 每段异步 continuation 重新带 scope；snapshot/terrain/cache/任务计数的归属、
  取消/异常/关闭/重试/释放必须明确，不复制 ThreadLocal 跨线程。
- 禁止同步 join/get。原地形采样、既有结构保护/成本和手绘路线不被改为默认 A*。
