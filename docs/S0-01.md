## 3. 当前阻塞与证据等级

### B01 严格依赖校验与离线缓存

**当前状态：已关闭。** 用户批准方案 A 后补齐 87 个 POM、22 个模块元数据文件，原生校验清单含 266 个 component，包含 Loom 的 JAR、POM、module。已移除临时代理并严格离线复测通过。过程中的额外二进制下载及撤销也完整记录在 [方案 A 报告](S0-01-metadata-repair.md)。以下保留修复前证据，不能误读为当前失败状态。

**已验证：** 保持 `--offline`、启用 Gradle 原生依赖校验时，插件解析在 `fabric-loom:1.16.3` 阶段失败；显式关闭该校验时，同一版本可以被解析、编译并运行测试。绕过插件 marker、直接解析 `net.fabricmc:fabric-loom:1.16.3` 也未解决。该实验性 resolutionStrategy 已撤销。

**已验证：** 本地有 Loom 1.16.3 JAR 和 Gradle 已解析的 `descriptor.bin`，但对应原始 POM 没有在检查到的 `files-2.1` 模块目录中。标准 `--write-verification-metadata sha256` 离线流程同样失败。

**推断：** 原始构建元数据缺口是校验开启后离线解析失败的原因。尚未通过补齐缓存后复跑证实，不能写成已完全定位的 Gradle 缺陷。

修复前校验 XML 是显式扫描本地已解析产物生成的 SHA-256 清单，含 193 个 component。`verify-metadata=false` / `verify-signatures=false` 明示它没有认证原始 POM 或上游签名；即便如此当时严格解析仍失败。此旧清单已经备份，**不是验收绕过手段**。

**后续授权：** 用户已批准一次性联网补齐这些已锁版本的构建元数据缓存。该步骤已执行并结束；后续构建恢复 `--offline`。版本锁未变，没有永久禁用严格依赖校验。

**已验证：** 现有实例 `assets/indexes/17.json` 的 SHA-1 为 `b39bbb1f62212e6725227460974d158b2f7e685c`，与实例版本 JSON 声明一致；索引列出的 3911 项均能在原实例找到文件。尚未逐项核对全部 object 内容 SHA-1，也未复制到 Loom 的独立缓存。

此项具备纯本地复用输入，不应直接改为联网下载游戏资源。B01 已关闭；后续应校验并复用本地资产到隔离缓存，不写现有实例。本次方案 A 没有执行客户端资产准备或启动。
